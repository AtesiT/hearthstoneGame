# EMBERFALL — «Пепел и Пламя»

Двухпользовательская коллекционная карточная игра по локальной сети (LAN),
вдохновлённая Hearthstone. Пиксельный стиль, процедурные звуки и арты,
авторитетный сервер: **вся логика и все секреты — на сервере, клиент тонкий**.

> **Локально, без интернета и без Docker.** Один узел запускает сервер,
> второй открывает его адрес в браузере — и можно играть.

## Запуск

```bash
npm install        # один раз (нужен только Node.js ≥ 18)
npm start          # сервер: http://localhost:8080
```

В консоли появится адрес «В сети» — его и открывает второй игрок
(оба устройства должны быть в одной сети).

Оба игрока заходят в меню, вводят ник, создают/входят в комнату по 5-буквенному
коду, жмут «Готов» — матч начинается.

## Тесты

| Команда | Что проверяет |
|---|---|
| `npm test` | юнит-тесты: лобби (RoomStore), движок, **античит-фазз** (71 тест) |
| `npm run sim` | headless-симуляция лобби: два «игрока» по WebSocket (19 проверок) |
| `npm run sim-game` | headless-симуляция **полной партии**: два ИИ играют до конца (13 проверок) |
| `npm run sim-reconnect` | обрывы/переподключение: лобби, в игре, grace, kick, оба (20 проверок) |
| `npm run sim-balance` | **баланс-пасс**: 200 партий движком, симметрия, манакривая (9 проверок) |
| `npm run test-ui` | headless-тест клиентского UI (jsdom): стол, эмоции, звук, арт, коллекция, лог (78 проверок) |
| `npm run art` | регенерация пиксель-арта (34 PNG, без зависимостей) |

Симуляции требуют запущенного сервера: `npm start` в одном окне,
`npm run sim-game` (и т.п.) — в другом. Исключение: `sim-reconnect` и
`sim-balance` поднимают сервер/движок сами.

## Как играть (правила)

- У каждого героя **30 HP**. Победа — уничтожить героя противника.
- Каждый ход: +1 кристалл маны (до 10), вытягивается карта.
- Рука — до **10** карт (лишняя сгорает), поле — до **7** существ, колода — 30 карт.
- Колода пуста → «усталость»: растущий урон герою (1, 2, 3, …).
- **Монета зари** — бесплатная карта (+1 мана в этот ход). Как в Hearthstone,
  она достаётся **второму** игроку, а **первый игрок не добирает карту
  на первом ходу** — это компенсирует преимущество первого хода (баланс:
  первый выигрывает ~57% партий у случайных ботов).
- Ключевые слова: **Провокация** (таунт), **Рывок** (чардж), **Божественный щит**,
  **Яд**, **Боевой клич**, **Смертный хрип**, ауры.
- 30 карт: 15 существ, 10 заклинаний, 5 видов оружия.
- Атаки: существо бьёт (и получает встречный урон), оружие бьёт без
  контратаки и тратит прочность. Провокация закрывает поле и героя;
  оглушённое существо бить и бить им нельзя; Яд убивает при любом уроке.

## Арт, звук, эмоции (Этап 4)

- **Пиксель-арт** лежит в репозитории (`public/assets/cards/*.png`,
  `public/assets/heroes/*.png`) — игра работает полностью офлайн.
  Генератор: `npm run art` (16×16, 8-бит, детерминирован).
  Если файл арта вдруг отсутствует — процедурный fallback + серый плейсхолдер.
- **Звук** — процедурный WebAudio-синтез (без аудиофайлов):
  `public/js/audio/sfx.js` (ходы, атаки, смерти, победа/поражение, 8 эмоций)
  и `public/js/audio/music.js` (меню- и battle-темы, кроссфейд).
  Кнопка «♪» на столе — mute. Настройки: localStorage.
- **Эмоции** — 8 штук (Привет, Спасибо, Угроза, Смех, Печаль, Удивление,
  Похвала, Огонь): панель над рукой, пузырь над портретом у второго игрока,
  серверный троттлинг 1/с (`send_emotion`).

## UX (Этап 5)

- **Коллекция карт** (из меню): все 30 карт с артами и редкостями,
  фильтры по типу, сортировки, детальный просмотр с полным текстом
  и словарём ключевых слов.
- **Настройки**: громкость музыки, звуки вкл/выкл, подсказки вкл/выкл
  (localStorage, применяются сразу).
- **Тултипы**: наведение на существо в руке/на поле — полный текст карты,
  текущие статы, статусы (оглушение, щит).
- **Подсказки**: контекстные строки на столе («Действий нет — завершите ход»,
  «Поле полное», …).
- **Боевой лог**: выдвигающаяся панель (кнопка «☰ Лог» или клавиша **Л**) —
  вся партия на русском: ходы, карты, атаки, смерти, эмоции.

## Надёжность (Этап 6)

- **Античит-фазз** (`npm test`): 2000 случайных команд в живой партии —
  ни одного исключения, любая отклонённая команда **не меняет состояние**
  (snapshot до = после), приватность снапшотов (нет seed/чужой руки/порядка
  колоды у обоих сидов).
- **Reconnect** (`npm run sim-reconnect`): обрыв в лобби и в игре (возврат по
  токену, resync-снапшот, `opp_back`), истечение grace (`opp_left_final`,
  комната в лобби, сид освобождён), двойное соединение (старое — `kicked`),
  оба отключились одновременно.
- **Баланс-пасс** (`npm run sim-balance`): 200+ партий движком — 0 исключений,
  симметрия побед ~50/50, все матчи заканчиваются `hero_kill`, длина ~20 ходов.
  По результатам **первый игрок больше не имеет перекоса**: монета — у второго,
  первый не добирает на 1-м ходу (HS-модель). Первый ход теперь ~57% вместо ~65%.

## Архитектура (кратко)

```
public/          тонкий клиент (HTML/CSS/JS, без серверной логики)
  js/net/        WebSocket-клиент: автореконнект, ping, переподключение по токену
  js/ui/         машина экранов (меню → лобби → ожидание → матч)
  js/game/       UI стола: рендер снапшотов, выбор целей, анимации, процедурный арт
server/
  game/          ДВИЖОК — единственный источник истины: ходы, мана, эффекты,
                 валидация, смерти, ауры, победа (rng.js, cards.js, engine.js)
  net/           RoomStore (лобби), NetServer (WS), диспетчер сообщений,
                 sanitize.js — ViewState: своя рука видна, чужая — только счётчик
docs/00-ANALYSIS.md   полный разбор: стек, протокол, правила, план этапов
scripts/       headless-симуляции (лобби, полная игра, UI)
```

**Протокол:** клиент шлёт команды (`play_card {handUid, target, ack}`, `end_turn {ack}`),
сервер отвечает **полным снапшотом** (`state`) + событиями с `seq > ack`.
Клиент не знает правил — валидные цели для карт приходят в снапшоте.
`rngSeed` и содержимое колод в снапшот не попадают (античит).
